What this is

Two lookup tools published from one GitHub repository, backed by two federal datasets that each do a job the other cannot.

BLS tells you what an industry averages. It is a survey, so it can never describe one employer. OSHA tells you what a specific establishment filed. It is not a representative sample, so it can never describe an industry. The tools keep those roles separate.

industries.json

Maps a NAICS code to the codes BLS buries inside its series identifiers. Built once from BLS's is.series file; only needs rebuilding if BLS restructures its industry coding, which is rare.

FieldExampleMeaning
naics236NAICS subsector. Empty string for the all-industries total.
labelConstruction of buildingsPlain-language name shown in dropdowns.
ssCONBLS supersector code. Letters, not digits.
ind236000BLS industry code, six digits, NAICS right-padded with zeros.
groupConstructionSector heading used to group the dropdown.

Coverage is 96 NAICS subsectors — the three-digit level. OSHA records carry six-digit codes, and both pages walk a code up to the nearest published level, so 238110 resolves to specialty trade contractors on its own.

BLS does not publish private-industry rates for the six public administration subsectors (921 to 926) or for management of companies (551). Those appear in this file but have no matching rates.

industry-rates.json

BLS Survey of Occupational Injuries and Illnesses. Private industry only, rates per 100 full-time workers. Covers 2014 onward.

Structure nests four levels deep:

rates → NAICS → measure → area → year → value

So rates["236"]["31"]["106"]["2024"] is the 2024 total recordable case rate for building construction in California.

Top-level keys

KeyContents

stateAreasPostal code to area code, e.g. CA to 106. Lets the lookup page find a state's own rate.

Measure codes

Two characters: BLS data type, then case type. All current entries are data type 3, rates per 100 full-time workers.

CodeMeasure
31Total recordable cases
32Days away, restriction or transfer (DART)
33Days away from work
34Job transfer or restriction only

33 and 34 sum to 32. The tools use 31 and 32.

Area codes

Three digits: a leading 1 for private industry, then BLS's own two-digit area number. These are not FIPS codes and cannot be derived — they come from BLS's is.area file. 100 is national.

State estimates are suppressed where a state's sample is too thin, and published at coarser industry detail than national figures. Gaps are expected; the lookup page falls back to national when a state figure is missing.

data/manifest.json

The index the lookup page reads first. It lists which states exist and which years each one has, so the page can populate the dropdown without downloading anything.

{
  "states": {
    "AK": ["2016", "2017", "2018"],
    "AL": ["2016", "2017", "2018"]
  }
}

This file is the single source of truth for what the page offers. Remove a state here and it disappears from the dropdown, whether or not its data files are still present. Add one without uploading its files and it will appear but fail to load.

It must sit inside the data folder, not at the repo root.

It is ordinary text and safe to edit by hand — useful for dropping territories or stray codes after a conversion. Mind the JSON punctuation: entries are separated by commas, and the last one must not have a trailing comma.

data/ita-XX-YYYY.json

OSHA Form 300A establishment filings, one file per state per year. XX is the lowercase postal code, YYYY the calendar year the injuries occurred.

Rows are stored as arrays rather than objects — the same 15 values in the same order every time, which roughly halves the file size.

  "state": "CA",
  "year": "2024",
  "fields": ["year", "name", "address", ...],

Dropped during conversion: industry_description (long text, repeated on every row, and derivable from NAICS), establishment_type, size, company_name, ein, and the day-count columns K and L. Add them back by editing the OUT list near the top of prep.html.

OSHA's own establishment_id is deliberately not carried. It is reissued when a filer recreates a profile in a later year, so it cannot track one location over time. The pages group on normalised name, state, ZIP and street number instead.

How rates are computed, and what they can't tell you

Both rates use OSHA's published formula. The 200,000 is 100 full-time workers at 2,000 hours a year, which is what puts an establishment on the same basis as a BLS industry figure.

Total case rate = (H + I + J) × 200,000 ÷ hours worked

DART rate       = (H + I)     × 200,000 ÷ hours worked

Where H is days-away cases, I is job-transfer or restriction cases, and J is other recordable cases. Both are computed at conversion time and stored, so the pages do no arithmetic on the fly.

Limits that matter when someone acts on a number

  • OSHA validates almost nothing. Names, addresses, NAICS codes, headcounts and case counts are all stored as typed. A mistyped hours figure moves a rate by an order of magnitude. The lookup page flags anything implying under 800 or over 3,200 hours per employee per year, but a plausible-looking wrong number passes.
  • Absence is not a clean record. Reporting is required only above certain size and industry thresholds, so most employers never file. An empty search result means no data, not no injuries.
  • Matching is fuzzy by necessity. There is no shared identifier between a submission and an OSHA filing, so the page ranks candidates by name similarity and leaves the choice to you. Confirm the address.
  • NAICS is not a class code. The two systems do not correspond, and one NAICS subsector can span several classes with very different hazards. Nothing here determines a classification.
  • Recordables are not claims. OSHA recordability and workers' compensation compensability are different tests that overlap without matching.
  • The datasets end in different years. BLS runs about a year behind, so the most recent establishment year may have no industry figure to compare against yet. The ratio shows a dash rather than guessing.

Refreshing the BLS industry rates

Once a year, after BLS publishes. The 2024 figures came out in January 2026, so expect roughly that timing. About twenty minutes, most of it downloading.

  1. Go to download.bls.gov/pub/time.series/is/ in a browser.
  2. Download is.data.1.AllData. Around 241 MB.
  3. Download is.area from the same page. 10 KB, instant.
  4. Open rates-prep.html by double-clicking it on your own computer. It should show two file boxes; if it shows one, you have an old copy.
  5. Select both files and press Extract. A few minutes.
  6. Save the result as industry-rates.json and replace the one in the repo.

The page reads area names from is.area rather than assuming them, which matters because BLS area codes are not FIPS and cannot be guessed.

Nothing else changes. industries.json only needs rebuilding if BLS restructures its industry coding.

You'll know it worked when the Area dropdown on the chart page lists states. If it is empty, the old file is still in place.

Refreshing the OSHA establishment data

Once a year. Employers file between January and March for the previous calendar year, and OSHA updates the published files quarterly, so a refresh any time from mid-year onward captures a reasonably complete year.

  1. Go to osha.gov/itadata and download the Form 300A summary files for whichever years you want. Each arrives as a .zip.
  2. Unzip them. The converter reads .csv, not .zip.
  3. Open prep.html by double-clicking it on your own computer.
  4. Select all the CSVs at once. One pass handles every year.
  5. Type ALL in the state box to keep every state, or a single postal code for one.
  6. Leave the exclusion box as WA,OH,WY,ND — monopolistic fund states with no private market. Add PR,VI to drop those territories too.
  7. Press Prepare. Several minutes for the full national set.
  8. Press Build one zip with all states. Compression takes a few more minutes and shows a percentage.
  9. Unzip the result. It contains a data folder with every state file and the manifest already inside.

The per-state buttons underneath rebuild a single state without redoing everything — useful when only one or two states need updating.

Two things that reliably go wrong. Leaving the state box on ALL when you meant one state produces files far larger than GitHub's 25 MB web upload limit. And some extraction tools add a wrapper layer, leaving data/data/; the files must sit exactly one level down.

Uploading and verifying

Use GitHub Desktop, not the website. The web uploader caps files at 25 MB and struggles past about a hundred at once; a full refresh is roughly 470 files.

  1. In GitHub Desktop, Repository → Show in Explorer. That opens the repo folder on your PC.
  2. Copy the new data folder in, replacing the old one. Put industry-rates.json at the root alongside the HTML files.
  3. Write a summary saying what changed and which states you excluded — in a year you will want to know whether a missing state was deliberate.
  4. Commit to main, then Push origin.
  5. Wait a minute for GitHub Pages to rebuild.

The folder layout the pages expect:

Troubleshooting

What you seeWhat it means
There isn't a GitHub Pages site hereThe site isn't built or isn't enabled. Often just a rebuild in progress after a rename — wait a minute.
404 — File not found (with the parrot)The site exists, that file doesn't. Usually a filename mismatch: a capital letter, or an extension lost on download. Paths are case-sensitive.
NetworkError when attempting to fetch resourceThe request never reached a server. A wrong address or a missing file.
Couldn't read data/manifest.jsonThe data folder isn't uploaded, is nested one level too deep, or the manifest sits at the root.
Area dropdown emptyindustry-rates.json is the older national-only version. Re-run rates-prep.html with is.area.
BLS publishes no figure for that industry and measureA genuine gap, not a fault. State estimates are suppressed where the sample is thin.
Reported hours work out at N per employeeThe filer's numbers are implausible. Treat the rates as unreliable and verify before using them.
No match on a searchMost likely the employer is below OSHA's reporting threshold and never filed. Try fewer words, or drop the city filter.

A note on BLS's API

An earlier version of this project called api.bls.gov live. It returned 429 Too Many Requests persistently, from a Cloudflare Worker and from a home connection alike. That is why the data is downloaded once a year and read from this repo instead. If anyone suggests reconnecting it, this is the reason not to: the figures change annually, and a live call adds a way for the tool to fail at the moment someone is using it.

Where this goes next

Everything here downloads a whole state into the browser to search it. That ceiling is reached when you want OSHA's Form 300/301 case detail, which carries occupation codes and injury mechanisms for the class-fit work. At that point the data wants a real database — Cloudflare D1 — and the matching moves out of the page and into a Worker. Not before.
